Writing workflow

Follow the story.
Keep the thread.

Five perspectives, one creative direction: yours. Researcher, World Designer, Story Builder, Scene Writer, and Editor help develop the same project.

In the plugin, these are roles in a conversation, not five independently running models. In the desktop app, choose the writing step you need. You do not have to draft a manuscript to use the research and planning tools.

Begin with a creative brief

Describe your concept, genre or blend, tone, audience, and form. A realistic household is as valid a setting as a fantasy universe. There is no fixed genre list or required three-act structure.

/author-studio start A warm contemporary romance about
rival bakery owners. A novella, grounded, with no supernatural elements.

Examples on this page use Copilot CLI. In Claude Code, replace /author-studio with /author-studio:author-studio.

These are actions after the skill command, not global host commands. Use /author-studio help, not the host's /help.

Prose chapters normally run 1,000–3,000 words unless you request a different length. For a standalone short piece, agree on its scope and use draft 1 for the whole work. Scenes and serial installments can also be numbered units.

Review before canon changes

Work at or below 75% confidence, an absent or invalid rating, or a reported contradiction requires human review before proposed canon or progress changes are accepted. Unfinished desktop artifacts also wait for review. Work above the threshold can be accepted automatically when the other checks pass.

Confidence is a model's subjective assessment, not a measured probability or a guarantee of quality. Plugin gates are instructions followed by the host model, not a deterministic enforcement engine.

In the desktop app, use the review controls. In the plugin, reply through the skill with one of these directives:

  • APPROVE accepts only the displayed proposal and stops. A contradiction needs an explicit canon resolution.
  • MODIFY: <notes> revises the pending proposal and requests review again.
  • REJECT discards the proposal, not accepted work. It does not automatically regenerate.

Other worker commands are blocked while review is pending. Approval does not automatically start the next phase.

The desktop app may make up to three assessment-only requests to recover a missing confidence rating. This uses additional tokens, does not rewrite the artifact, and never bypasses an unfinished response or canon conflict. If assessment cannot be recovered, the artifact waits for you.

Desktop YOLO mode under Write drafts through a selected last chapter, but pauses whenever review is needed. It is an explicit opt-in, not the normal one-step workflow.

Get a second pair of perspectives

Optional automated review uses two independent read-only reviewers on different models. It consolidates findings, suggested solutions, and disagreements. Reviews are advisory: they never approve work or change canon.

/author-studio-review pending
/author-studio-review chapter-2-v1 focus on clue fairness

In Claude Code, use /author-studio:author-studio-review pending. While a human review gate is pending, only that candidate can be reviewed.

The plugin requires a host that can run agents and select a model per invocation; otherwise it explains the limitation and asks before offering a single-perspective alternative. Each review uses two additional model calls. In the desktop app, configure reviewer model connections separately.

Keep manuscript and planning separate

Chapters contain prose, not continuity appendices. Structured timeline events, open threads, and planned beats enter the Story bible when accepted. Recognizable list-only planning appendices are separated for review and excluded from manuscript word counts and exports.

In the desktop app, export the manuscript as a Word document from Manuscript. Use Export… or File → Export Project Content for research, setting, story plans, a story bible, or a planning packet as Word, Markdown, or plain text. These exports include accepted content, not pending or rejected proposals.

History → Back up project preserves the full desktop project. History → Export state file for the plugin transfers the story bible and progress, but not the full manuscript. See saving and resuming before switching hosts.
